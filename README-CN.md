# A native AOT compiler for ActionScript 3

把 ActionScript 3 源码**提前编译（AOT）成原生机器码**，生成原生可执行文件——同时保留你熟悉的 AS3 语法。

设计思路：编译器前端只负责
`词法 → 语法 → 生成可读的 C`，优化与机器码生成全部交给成熟的 C 编译器，不重复造轮子。

## 编译管线

```
ActionScript 源码 (.as)
        │  lexer.ts      词法分析（token）
        ▼
        │  parser.ts     递归下降解析（AST）
        ▼
        │  codegen.ts    语义 + C 代码生成
        ▼
       C 源码 (.c)
        │  构建编排 src/build.ts
        │  （构建清单 JSON + -I/-L/-l/-D + --target）
        ▼
  ┌──────┴───────┐
  │ native        │  cc/clang -O2 -lm            → 原生可执行（Mach-O / ELF / PE）
  │ wasm          │  clang --target=wasm32-wasip1  → WASI .wasm
  └──────────────┘
```

「生成单个可读 `.c`」是**默认形态**（构建简单、便于阅读），不是禁止链接第三方库的铁律：
实现图形（skia/cairo/SDL）等重活时，正确做法是把成熟库**链接**进来（`-lskia`），而不是自研光栅化。
参见「构建与链接」与 AGENTS.md §2.9。

## 运行

安装（得到 `as-aot` 命令）：`npm install -g as3compiler`（或本地开发 `npm link`）。
未安装时可用 `node src/index.ts ...` 或 `npm run compile -- ...` 等价调用。

依赖：Node ≥ 22.6（原生支持直接运行 `.ts`，无需编译步骤）、系统装有 `cc`/`clang`；
`--target wasm` 需 WASI SDK（`WASI_SDK_HOME` 指向 SDK 根，或自带 wasm32 后端的 LLVM clang），
且运行产物需支持异常处理提案的运行时（wasmtime/wasmer，见 `docs/zh-cn/compile.md` §2）；
`--target wasm --package web` 需 Emscripten SDK（`EMSDK_HOME` 指向 emsdk 根目录，见
`docs/zh-cn/html5-web.md`）。

```bash
# 编译（默认输出到输入同名的无扩展名文件，并保留生成的 .c 便于阅读）
as-aot examples/hello.as

# 编译并运行
as-aot examples/fib.as --run

# 指定输出名 / 指定 C 编译器
as-aot examples/class.as -o build/class --cc clang --run

# 生成 macOS App 工程（--package xcode-project，交给 Xcode 打开/构建/调试，产物是 .app）
as-aot src/Main.as --target native --package xcode-project -o build/Main

# 生成浏览器 HTML5 渲染页面（--target wasm --package web，需 Emscripten SDK）
as-aot examples/web/hello-web.as --manifest examples/web/hello-web.build.json
```

## 构建与链接

> 完整编译说明（命令行参数、构建清单 JSON、多目标后端、WASI 工具链）见
> [`compile.md`](docs/zh-cn/compile.md)。

支持多目标与链接第三方库：

```bash
# WASI 目标（需装 WASI SDK 或自带 wasm32 后端的 clang）
as-aot examples/hello.as --target wasm

# 链接第三方库（skia/cairo/SDL 等）：include 路径 / 库路径 / 库 / 宏定义
as-aot app.as -I vendor/include -L vendor/lib -l skia -D USE_SKIA=1

# 构建清单（JSON，路径相对清单目录解析）
as-aot app.as --manifest examples/skia-link.build.example.json

# 导出顶层函数给 JS 直调（默认 WASI 命令模块只导出 _start）
as-aot examples/wasm-native/fib.as --target wasm --export fib

# 声明式导出：用 [WasmExport] 元数据标记函数/静态方法，自动导出并生成 .exports.json
as-aot examples/wasm-native/export-meta.as --target wasm

# 生成浏览器 HTML5 渲染页面（--target wasm --package web，需 Emscripten SDK）
as-aot examples/web/hello-web.as --manifest examples/web/hello-web.build.json

# 只生成 C 并打印编译命令，不真正编译（无工具链时验证命令）
as-aot examples/hello.as --target wasm --dry
```

构建清单（JSON）字段：`target`（`native`/`wasm`）、`package`（`raw`/`xcode-project`/`android-project`/`web`，
默认 `raw`，见 `compile.md` §6）、`c-compiler`、`opt`、`sources`（额外 C/C++ 源）、
`include-paths`、`link-libs`、`link-paths`、`defines`、`objects`（预编译 `.o`）、`exports`（导出到 .wasm 导出表的 C 符号）、
`font-urls`（`--package web` 的字体字节流 URL 列表，运行时注入 Skia），
以及 `xcode-project` 的应用元数据 `bundle-id`/`display-name`/`icon`/`deployment-target`（见 `compile.md` §6.4）。CLI 参数覆盖清单同名字段。
路径类字段相对清单文件所在目录解析。示例见
[`examples/skia-link.build.example.json`](examples/skia-link.build.example.json)。

**按目标分层链接（`targets`）**：顶层字段为公共默认；`targets.<native|wasm>` 块只对**匹配的目标**生效，
并把它声明的字段**整体替换**（replace，非追加）同名顶层值——使**一份清单**即可服务链接集互斥的多目标
（典型：native 链接 curl，而 WASI 无 socket、`-lcurl` 会让 `wasm-ld` 失败，需为 wasm 去掉它）。合并顺序：
默认配置 → 清单顶层 → 清单 `targets.<最终目标>` → CLI 覆盖。示例
[`examples/flash-net-layered.build.example.json`](examples/flash-net-layered.build.example.json)，详见 `compile.md` §4.1。

| `Vector.<T>` | `as_vector_<T>*`（按元素类型 `T` 单态化：连续元素数组 `T* data` + `length`/`capacity`；索引越界 `throw RangeError`；编译期强制元素类型；`push/pop/join/indexOf/slice/concat/splice/forEach/map/filter/sort/reverse`、`.length` 读写、带参构造 `new Vector.<T>(length, fixed)`、字面量 `new <T>[...]`） |
| `Function` | `as_fn`（指向闭包记录 `{ thunk, env }` 的指针；每个被用作值的函数生成一个 thunk，把装箱参数列表解箱、调用带类型的实现、再把结果装箱回 `as_value`；捕获外层局部变量的闭包额外生成环境 struct + 堆分配构造器，env 指向该环境） |
| 对象字面量 `{}` | `as_object*`（字符串键关联数组，属性值装箱为 `as_value`） |
| `RegExp` | `RegExp*`（`{ vtable; as_regex* compiled; source; flags; lastIndex; global/ignoreCase/multiline/dotall/extended }`；`compiled` 为内嵌回溯 VM 的编译产物，构造时编译，编译错误抛 `SyntaxError`） |
| 类 `Foo` | `struct Foo` + `Foo*`；首成员为 `Foo_vtable*`（虚表：`super` 链 + 方法/getter/setter 函数指针，统一扁平槽列表保证子类 vtable 与父类前缀布局兼容）；字段平铺（父类字段在前）；方法编译为 `Ret Foo_method(void* this, ...)`，调用走 `obj->vtable->method(obj, ...)`；实例 getter/setter 同为虚派发（`obj->vtable->get_prop(obj)` / `obj->vtable->set_prop(obj, v)`），静态访问器与 `super.property` 仍静态直调；命名空间内的类用包前缀命名（`foo.bar.Baz` → `foo_bar_Baz`） |
| 接口 `I` | `struct I`（引用对：`void* obj` + `I_vtable* vt`）；方法派发走 `ref.vt->method(ref.obj, ...)`；每个实现类生成接口 vtable 实例 `Class_I_vt` |
| `Error` / 异常 | `struct Error`（`vtable` + `message`）；`throw` 归一化为 `as_throw(Error*)`，异常状态存于全局 `as_exception`，跳转栈用 `setjmp`/`longjmp`；`TypeError`/`RangeError`/`ArgumentError` 为 `Error` 子类（同布局、独立 vtable），`catch (e:Type)` 用 `as_is` 沿 `super` 链精确匹配 |
| `static` 成员 | 类级字段/方法：文件作用域全局 `Class_field` / `Class_method(...)`（无 `this` 接收者） |
| `trace` | 按类型生成 `printf` 格式串；对象打印为类名（`as_obj_to_str` 读 vtable 的 `name`） |

## 当前限制（v0.4.25，刻意保持极简）

- TextField `wordWrap` 断行阈值对齐 AIR（①，默认生效）：AIR 的可用宽度是**字段宽减 4px**（每侧 2px 内边距），此前按字段全宽排版，会让**行宽恰好贴边**的字段晚一个词换行。受控扫描六组文本（0/1/2 个尾空格、词间空格、双词）后确认阈值恒为 `ceil(墨迹宽 + 4)`，AOT 与 `adl 51.4.1` **六项逐值相同**。
- 具名增强开关（`--features` / 清单 `features`）：把「一个 AIR 超集能力」做成**具名开关**打开，而不是让用户手写背后的宏——`--features svg` 等价于 `-D ASC_USE_SVG=1`。**默认全关**（不开时产物与 `adl` 逐字节同构）；开了会在构建横幅点名 `== enhancements: svg (-D ASC_USE_SVG=1) ==`；**未知名字报错**（`--features lottie` → `unknown feature 'lottie' (known: svg)`，且在生成任何代码前退出）；**目标不支持也报错**（`--target wasm --features svg` 直报，而不是把 `undefined symbol: sk_svg_*` 甩给链接器）。`--air-app` 会把选择**持久化**进生成的清单（否则它每次整份重写会把手改抹掉），下次不带参数依然生效并打印 carry-over 提示；`--features none` 关闭。详见 [`docs/zh-cn/compile.md`](docs/zh-cn/compile.md) §3.4.2。
- SVG 运行时解码（E1，native、默认关闭）：`--features svg`（= 定义 `ASC_USE_SVG=1`）后 `Loader.load("*.svg")` / `loadBytes` / `BitmapData.loadFile` 均可解码——SVG **不是 `SkCodec` 格式**，走的是一条独立通道（`SkSVGDOM` 解析 → `SkSurface` 光栅化 → ARGB），`<text>` 经 `SkFontMgr` 正常出字，无绝对尺寸的文档按 SVG 规范默认 **300×150** 渲染。**默认构建与 AIR 逐字同构**（`ioError #2124 unknown type`，实测 `adl 51.4.1` 一致）；web 侧 Skia 未编 `expat`/svg，定义该宏会在**链接期**报错（不静默降级）。详见 [`docs/zh-cn/enhancements.md`](docs/zh-cn/enhancements.md) §4.1。
- 链接时/分阶段优化（E12，默认关闭）：构建清单 `lto`/`pgo`/`pgo-dir` 或 CLI `--lto` / `--pgo` / `--pgo-dir`。`-flto` 会同时加到**每个编译步与链接步**（只加一侧不报错、只是静默不生效，故由单一 `perfFlags()` 供四个命令构造器取用，回归逐步骤断言）；PGO 两阶段必须同名 `pgo-dir`（clang 读 `<dir>/default.profdata`，缺失即硬报错不静默降级）。仍属「前端只翻译、优化交给 `cc -O2`」——一行优化都不手写。实测调用密集负载 `-O2` ~30.6 ms → `-O2 -flto` ~25.6 ms（校验和三者完全一致）。详见 [`docs/zh-cn/compile.md`](docs/zh-cn/compile.md) §4.2。
- 体积优化（阶段七十八）：生成 C 里非导出的文件作用域函数（内建类方法体/thunk/free function）统一标 `static`，让 `clang -O2` 从 `main` 出发做调用图分析自动消除不可达的内建类（`hello.as` 二进制 165 KB → 34 KB）；`main` 与 `[WasmExport]` 导出符号保持全局。详见 [`docs/zh-cn/size-optimization.md`](docs/zh-cn/size-optimization.md)。
- 正则引擎为自研 ES3 回溯 VM，**字节/ASCII 语义**（`\w`/`\d`/`\s` 仅覆盖 ASCII，非 UTF-8 Unicode 感知）；`exec`/`match` 非全局捕获组未参与者返回 `undefined`。
- WASI 目标下 `Date` 分辨率退化为秒级（`gettimeofday` 是 POSIX 专属，WASI 以 `time(NULL)` 退化，见 `as_now_ms()`）。
- 静态字段的非常量初始化器（对象字面量 `{}`、`new X()`、函数值 `ClassName.method` 等）因 C 禁止非常量静态初始化，改为在 `main()` 入口按类声明顺序执行（各在声明类的静态上下文中求值）；实例字段初始化器在构造器内 `super()` 之后执行。
- `throw` 归一化为 `Error`（字符串/基本类型会被包装为 `Error`）；`catch (e:Type)` 按 `super` 链精确匹配（`TypeError`/`RangeError`/`ArgumentError`/`ReferenceError` 已实现，可被基类 `catch (e:Error)` 兜底捕获）。
- `finally` 在正常完成、抛异常、以及 `return`/`break`/`continue` 从 `try` 块提前跳出时均执行（阶段七十七已补齐提前退出的异常栈回退 + finally 重发，`try { return } finally {...}` 不再跳过 finally）。
- 未捕获异常打印到 `stderr` 并以非零码退出。
- 位运算将操作数转换到 32 位整数（`int`/`uint`），移位计数按 AS3 语义对 32 取模；`>>` 对有符号整数做算术右移。
- 内存管理（阶段五十七，精确 GC）：运行时实现**自研 Mark-Sweep 垃圾回收**——`gc_alloc` 用分段堆（每段 1 MiB）+ free-list（first-fit + 切分 + 合扇）+ 每个对象前带 `gc_header` 三色位域；触发点为 **`Stage_dispatchFrame` 帧边界安全点**（所有帧回调已返回，根集合只剩永久根，故无需 shadow stack）调用 `gc_step()` 增量推进，另有 `System.gc()` 手动触发 `gc_collect()` 停机回收，以及**非 GUI 目标的分配阈值触发**（阶段八十九·四十一）：`gc_step()` 的唯一调用者就是帧边界，故它一旦被调用即标记「本程序帧驱动」；在此**之前**（纯脚本 / 服务端循环 / WASI 等没有帧的程序）`gc_alloc` 自己按 `max(下限, 在用堆/8)` 的阈值做一次停机回收，否则没有帧的程序会把「分配了多少」永久留在堆上；一旦派发过帧，分配阈值触发即让位给帧边界的增量回收（保住 GC-4 的每帧有界停顿）。**下限按路径二分**（阶段八十九·四十七）：帧路径仍是 1 MiB（切片推进、每帧停顿由 `gc_budget()` 限幅，小堆要及时开始），非 GUI 路径是 `GC_NONGUI_FLOOR` = **8 MiB**。依据是实测分解：一次停机回收的开销 65% 花在**重新标记存活集**（`gc_mark_drain`，binarytrees 恒为 ~1.05 ms/次，与「上次回收后累积了多少垃圾」无关），只有 ~20% 在 sweep、~0.3% 在保守栈扫描，故总 GC 时间 ≈ **次数 × 常数**，只能靠「少收」摊薄——按 1 MiB 下限 `binarytrees`（存活集 ~1 MB、高流失）要收 154 次（光标记就累计 166 ms），抬到 8 MiB 只收 24 次、总耗时 287 → 97 ms、`strings` 258 → 229 ms；代价是离屏程序最多多驻留一块下限的垃圾（`binarytrees` 峰值 RSS 9 → 15 MB，12 MiB 后性能饱和），`ASC_GC_THRESHOLD` 仍整体覆盖两条路径并是内存紧张目标（WASI/嵌入式）下调的开关。触发判定同时改为**缓存式**（`gc_trigger_next`，仅在回收后失效重算）：`gc_trigger()` 要汇总 24 个计数，而 `gc_alloc` **每次分配**都判定一次，逐次重算实测 ~11 ms/百万次分配（`binarytrees` 98 → 88 ms）。根集合 = 永久根（静态字段、模块变量、`ASC_win_stage`、ENTER_FRAME 事件注册表、定时器）+ 内建根（`as_exception`）。**`System.gc()` 可在任意位置（含活着的 AS3 帧内）触发**，此时只有 C 局部变量持有的对象没有任何登记，故 `gc_mark_roots()` 末尾追加一次**保守栈扫描**（`gc_mark_stack()`）：`GC_NOTE_STACK_BASE()` 在 `main` 首行锚定窗口上界，扫描 `[SP, 上界)` 的每个对齐字，仅当该字指向 GC 段内且头部 tag/color/size 全部合法才当根（`GCT_*` 常量偏移 `GCT_TAG_BASE`、空闲块 `type=0`，故任意垃圾位模式都不可能被误认为对象头）；误保留只延续到下一次采集。标记沿对象类型（数组/对象/Dictionary/闭包/类实例/字符串）分派 `gc_scan`，类实例经 vtable→props 反射表沿 super 链标记（tag 3/6/7 分派 `gc_mark_ptr`/`gc_mark_value`）；未达对象扫回 free-list 复用。**GC-2** 已将字符串（拼接、转换、`split`/`substring` 等）迁入 GC 堆（`as_str_alloc`），彻底清零字符串 arena 泄漏；**字节缓冲也已在阶段八十九·四十二迁入 GC 堆**（新增叶子类型 `GCT_BYTES`）：`ByteArray` 的 grow/compress/uncompress/URL 二进制读与 `BitmapData.pixels` 全部由 `gc_alloc(GCT_BYTES, n)` 产生，旧缓冲只被丢弃（不再 `free`/`realloc`，`dispose()` 也改为丢引用——`free` 一个 GC 缓冲会砸坏 GC 空闲链），图片解码时 glue `malloc` 出来的 ARGB 缓冲 `memcpy` 进 GC 缓冲后再 `free`（保证同一字段所有权单一），所有写入这些字段的位置补 `gc_write_barrier`；`Context3D_submit` 每帧每流的顶点反交织临时缓冲从 `malloc`/`free` 改为**缓存复用**（`as_s3d_upload_vertex` 是同步拷贝）。剩余不在 GC 堆的缓冲只有：glue 内部短命缓冲、像素读回缓冲 `ASC_stage3d_pixels`、以及对数/JSON 构造器等 runtime 自己的 `malloc`（用完即 `free`）。闭包 env 与 `as_vector` 已迁入 GC 堆（`GCT_CUSTOM` 回调标记 + 引用元素用 `GCT_PTR_ARRAY` 缓冲），**`Vector.<T>` 的标量/装箱/接口元素负载也已迁入 GC 堆**（阶段八十九·二十四：新增叶子类型 `GCT_RAW`，扩容收敛为单一助手 `as_vector_*_grow`；驱动是「Benchmark 场景 23 s 涨到 14.3 GB」——旧 `realloc` 负载在 GC 堆外永不回收，而 Starling 每帧重传多 MB 顶点缓冲），`VertexBuffer3D`/`IndexBuffer3D.uploadFromByteArray` 同时改为按绝对下标**就地复用**缓冲。保守栈扫描的地址门限同步收紧到 `p >= 段基址 + sizeof(gc_header)`（否则落在段首的栈字会让头部读取越界到段前未映射页而 `SIGBUS`）。**GC-4** 引入**增量标记**：三色状态机 + 显式灰栈 + Dijkstra 写屏障（`gc_write_barrier`/`gc_write_barrier_value`），`gc_step()` 每帧分摊一片 mark/sweep 切片，单帧停顿从 O(堆) 降到 O(切片)。**切片与触发阈值随堆自适应**（阶段八十九·二十五）：`budget = min(堆内对象数/16 + 500, 8000)`、`threshold = max(下限, 在用字节/8)`（该阶段下限统一为 1 MiB；**阶段八十九·四十七起离屏路径改用 `GC_NONGUI_FLOOR` = 8 MiB**，见上）——固定 500/帧只约束停顿不约束吞吐，十万对象级活集要走完一轮需数百帧、期间每帧新产生 2~4 MB 垃圾，实测堆膨胀到 917 MB 并反噬帧率（120→75），是「AOT 比 ADL 慢」的真因；切片必须封顶（不封顶时切片随堆线性增长，帧率反而从 120 滑到 47）。分配器同步改为**按尺寸类分链**（`gc_free` <256 KiB / `gc_free_big` ≥256 KiB，新段按请求类选 64 KiB/1 MiB，≥256 KiB 的 `Vector` 负载容量上取整到 2 的幂）——单链首适会把 freed 的多 MB 负载被小对象蚕食切碎，导致下一个多 MB 请求每帧新开段（实测 `resv=1127MB` 而其中 1 GB 空闲不可用）。调参旋钮：`ASC_GC_BUDGET`/`ASC_GC_THRESHOLD`，诊断开关 `ASC_GC_STATS` / `ASC_FRAME_STATS`（后者每 512 帧打印帧时 `p50/p95/p99/max`、GC 占比、RSS/`heaptotal`/在用/段数/空闲字节，用于分辨「卡顿是 GC 还是场景本身」）；mark 期新对象直接 BLACK（`gc_new` 侧链表，sweep 后归位），写屏障注入 setter（`as_array_set`/`as_object_set`/`as_dict_set`/`as_dyn_set`）、运行时构造器与用户直接字段写（`o.field = v`）。**段归还与分配器让步**（阶段八十九·二十六）：`gc_seg` 增加在用字节计数 `free_bytes`，限速 500 ms 的 `gc_release_empty_segs()` 把「全空」段先在两條空闲链上摘除其所有空闲块、再从 `gc_segs`/段地址表摘除并 `free`（调用点 = 轮末 `gc_finish_cycle` + 每帧 `gc_step` 的 IDLE 分支，后者保证**停止分配后** RSS 也跟随活集回落）；`free()` 只把页还给 `malloc`（macOS 实测 zone 把 263 MB “empty” 页常驻不还 OS），故同时显式调 `malloc_zone_pressure_relief()`（`#ifdef __APPLE__`）。段查表 `gc_in_heap()` 从「线性扫 ~1144 段」改为按基址排序的 `gc_seg_range` + 二分（+1 项缓存）——它被内联进 `gc_scan`，每个子指针/栈字/写屏障都要调一次，实测占主线程 **32.7%**，是「基准动画一卡一卡」的真根因（帧率 30~60、20 ms 停顿）。`VertexBuffer3D` 顶点负载从 `data`+`rawBits` 两份 double 合并为单份 `Vector.<uint>` 32 位字（`uploadFromVector` 窄化 float32 一次、`uploadFromByteArray` 端序一致时整块 `memcpy`、`submit` 直接读字），实测峰值对象 30144→**34080**、RSS 668→527 MB、活集字节 391→43 MB。`ByteArray` 逐元素端序判定改指针键缓存 + `as_ba_put/get_u32` 宿主序快路径（`strcmp` 曾占主线程 26.6%）。**段归还计数的精确性**（阶段八十九·二十七）：段归还是否安全，全看 `gc_seg.free_bytes == size`（「段内每个字节都在空闲链上」）是否真等价于「段空」——原先分配器从空闲链取块时、余量 < `GC_MIN_BLOCK`（32 B）就不切分但**仍按请求尺寸计费**，导致 `free_bytes` 比真实空闲**永久偏大**（每次 ≤31 B 累积）；偏差碰到「恰好等于段内活对象占用」时，`free_bytes == size` 成立，一个装满活对象的段被 `free` 还给 OS，malloc 立刻复用（实测给 arena/`ByteArray.data`），段内指针全部变垃圾——用户报的「第二次跑 benchmark 崩溃」真根因（`MeshStyle` 的 vtable 字与 **`gc_all` 链表头**都被写成同一个 double `0.9872449040412903`，即 benchmark 的 调研、八十九·四十八 A/B、八十九·四十九 G + 探针、八十九·五十一/五十二 C~I、**八十九·五十三 套接字层 + 静态自包含**）；其中 §4.1.1 以证据论证**不存在可覆盖 native/web/WASI 三端的单一通用网络库**（边界在**传输层**而非 TLS 原语），§7 是 socket 四类的实测语义与实现口径。`Keyboard` - `flash.net.SharedObject`（阶段八十九·四十）是**本地**共享对象的最小模型：持久化后端是 `applicationStorageDirectory` 下的 **JSON 文件**（`[<localPath>/]<name>.json`，经既有 `as_json_stringify`/`as_json_parse`），**不是 AIR 的 AMF3 `.sol` 容器**（AIR 的路径是 `Local Store/#SharedObjects/<swf>/<name>.sol`），因此语义（实例身份、`flush`/`clear`/`size` 的规则、退出时自动落盘）对齐 AIR、**字节格式与 `size` 的确切数值不对齐**（`size` 按 AIR 的口径取「将要持久化的表示的字节数」，我们的表示是 JSON，故偏小）；`data` 的读取在缺失键上返回 `null`（AIR 为 `undefined`，本子集既有口径）；`flush()` 的本地同步写要么成功要么失败，故失败**抛 `Error`** 而非像 AIR 那样返回 `"pending"` 稍后重试（静默回 `pending` 是假报）；`getRemote`/`connect`/`send` 抛错（无 FMS）；进程被 `SIGKILL`/`SIGTERM` 终止时未落盘的数据仍会丢失（`atexit` 只在正常退出路径执行，与 AIR 同类）。
- `flash.filesystem`（阶段六十四）为 POSIX 文件 IO 最小模型：`File` 把路径当普通字符串束（`nativePath` + 只读 `url` = `file://` 前缀），`exists`/`isDirectory` 为**只读属性**（getter，`f.exists` 而非 `f.exists()`）经 `stat()`、`createDirectory` 经 `mkdir`（支持逐级创建）、`deleteFile`/`deleteDirectory` 经 `remove()`（空目录）；静态只读 `applicationStorageDirectory` 返回应用可写、按应用隔离的存储目录（macOS 下 `~/Library/Application Support/as3aot/Local Store`，其余平台 `~/.as3aot`，按需创建——打包的 `.app` 以不可写 CWD 启动，故 `.` 不是安全写入目标）、`applicationDirectory`（映射 CWD `"."`）、`desktopDirectory`/`documentsDirectory`/`userDirectory`（`getenv("HOME")` 拼接 `Desktop`/`Documents`/裸 HOME 运行时解析）。`FileStream` 持 `FILE*` 句柄（不透明 `void*` 字段，非 GC 跟踪），`open` 把 AIR `FileMode`（`read`/`write`/`append`/`update`）映射到 C `fopen` 模式，`openAsync` 在同一 open 基础上**异步派发 `ProgressEvent.PROGRESS`（`bytesLoaded`=`bytesTotal`=文件大小）+ `Event.COMPLETE`**；`readUTFBytes` 返回 `as_str_alloc` **GC 跟踪**缓冲（不再 `malloc`）。`position`/`bytesAvailable` 为只读（`ftell`/`fseek`）。`NativeWindow`/`Window`（原生多窗口）与 `SQLConnection`/`SQLStatement`（SQLite 链接）全部**延后**。
- **异步 IO 是后台 job + 帧边界发布**（阶段八十九·四十五）：`URLLoader.load` / `Loader.load` / `Loader.loadBytes` / `FileStream.openAsync` 的读取（含图像**解码**）都在 job 里跑，结果先落 malloc 暂存，只在**下一个帧边界**（`Stage_dispatchFrame` 开头的 `as_async_tick()`）搬进 AS3 可见状态并派发事件——实测停顿 **99% 来自解码**（1568² `atlas.png` 解码 19.7 ms，而 1.3 MB 读只 0.1 ms），故只搬读等于没搬。**native（macOS/Linux pthread）用 4 worker 池真并发**（`ASC_ASYNC_THREADS`；实测 `load()` 立即返回、submit 恒 0 ms，drain = `⌈n/4⌉×20 ms` 而非 `n×20 ms`），web/WASI/Windows 保持同步内联（wasm 单线程模型下 pthread 需 COOP/COEP）；worker **绝不碰 GC 堆**（输入提交时拷到 malloc），在飞 job 的 AS3 目标由 `as_async_mark_roots` 标为 GC 根且 thunk 跑完前**不移出 job 表**（提前移出会被 sweep 清零，实测 SIGSEGV）；同一目标重复 `load()`/`openAsync()` 时旧 job 被取代（不再派事件，与 AIR 重启加载一致）。契约修正：`data`/`content` 在终态事件前**不可见**（此前同步读完就已可见）、补 `PROGRESS`、解码失败报 `IOErrorEvent` 而非空中空 Bitmap。headless 的 `tickTimers()` = 等 worker 排空 + 一次排空全部完成项（保例程确定性）。见 `examples/async-io.as`（含 5 组反向对照）与 `TODO.md` 阶段八十九·四十五；已知缺口：`LoaderInfo.PROGRESS` 仍不派发（Starling 监听的是 `URLLoader`）、`PROGRESS` 只派一次（读不分块，无中间水位）、纯 C 构建无解码器故图像加载报 IO_ERROR（解码成功路径由 skia 后端覆盖）。
- 浏览器目标（`--target wasm --package web`，阶段六十九）：用 Emscripten 把 Skia + C++ 胶水层编成浏览器产物（`.wasm` + `.js` + `index.html`），在 `<canvas>` 里跑 CPU 光栅 + `emscripten_set_main_loop` 帧循环；窗口层由 SDL2 换成 canvas blit，字体后端由 CoreText 换成 `SkFontMgr_New_Custom_Data()` + 运行时 `fetch` 注入（`font-urls`）。`<renderMode>direct</renderMode>`（或 `gpu`）时 Skia surface 换成 Ganesh `GrDirectContext` + WebGL2 后端、整帧 GPU 合成、present 仅为 `GrDirectContext::flushAndSubmit`（`ASC_RENDER_GPU=1`，去掉 CPU 软件光栅化瓶颈；`flush()` 只把命令发到驱动、GL 后端不调 `glFlush`，必须 `flushAndSubmit` 才真正提交，否则 FBO 0 呈现未初始化品红/碎片化，与 native Metal 后端的教训一致）。已知限制：字体运行时网络加载（离线/内网不可用）、**没有字体时文字会静默全部消失**（窗体背景照画、字形全无；`--air-app` 已加黄字警告点明，见 `html5-web.md` §4/§6）、半透明像素 premultiplied alpha 直贴 canvas 有色差（不透明精确）、整包 CJK 字体首屏加载较慢、详见 `docs/zh-cn/html5-web.md`。**Stage3D（阶段八十九·三十）**：整套渲染都走 `Context3D` 的程序（如 `examples/air-starling-demo`，142 个 AS3 源）在 web 上改链 `vendor/stage3d_webgl.cc`（WebGL2/GLES3 + AGAL→GLSL ES，`ASC_RENDER_STAGE3D=1` + `ASC_S3D_GLSL=1`）即可正常渲染——`s3d_*` 签名与 native Metal 后端一致，故生成 C 零改动（GL 侧 Y 轴翻转、BGRA 交换、逐寄存器 uniform、`DEPTH24_STENCIL8` 离屏 FBO、与 Ganesh 共享上下文等差异都在胶水内处理）；实测 12 个场景逐个进入并与 AIR `adl` 参考一致（120 fps / 0 丢弃 / 单帧 2.88 ms），Stage3D 上屏已是 **GPU 直连**（阶段八十九·三十一）：`sk_gl_draw_texture` 把渲染目标的 GL 纹理包成 `GrBackendTexture` 直接画进 canvas（对应 Metal 的 `as_skia_mtl_draw_texture`），单帧 `renderMs` 由 3.21 ms 降到 0.12~0.15 ms（**约 23×**），且与读回路径逐像素一致（读回作为 `ASC_RENDER_GPU` 未定义时的兜底保留）；详见 `docs/zh-cn/html5-web.md` §3.3/§6。**AGAL 比较指令（阶段八十九·三十二）**：`sge`/`slt`/`seq`/`sne` 的**全掩码**形态在 GLSL 侧译为 `mix(vec4(0.0), vec4(1.0), vec4(greaterThanEqual(a, b)))`（`mix(genType,genType,genType)` 是 ES 1.00 合法重载，`vec4(bvec4)` 由 §5.4.2 允许；`mix` 的 `bvecN` 重载是 ES 3.00 才有）——此前 MSL/GLSL 两支共用一个「三元格式串 `sprintf`」，因两支 `%s` 个数不同而 varargs 是同一份列表，拼出 `v0(greaterThanEqual(v0, vec4))`，web 上 Filters 场景点「Switch Filter」切到 Drop Shadow/Glow 即片元编译失败（native 侧恰好只用前 4 个实参所以从未暴露），现已拆成两个独立 `sprintf`，四个 opcode 两端都可用（`examples/stage80.as` 断言两侧完整形态）。**帧驱动与节拍（阶段八十九·二十九）**：web 帧由 `requestAnimationFrame` 驱动，**一次 rAF 回调 = 一个 vsync**；节拍按**整 tick** 表达（`skip = round(1000/frameRate / rAF周期)`，即每 `skip` 个 vsync 呈现一帧），rAF 周期由连续回调间隔的**中位数**实测（浏览器无 `SDL_GetDisplayMode` 对应物，`sk_window_get_display_refresh()` 在 web 返回 0）。修复前用的是「时间戳截止期」节拍，在 rAF 时间戳抖动（120 Hz 面板实测 p50 8.30 / p95 9.30 ms，周期 8.333 ms）下会丢/取交替、**速率减半**——rAF 给 120 次/秒却只呈现 **66 fps**、每秒丢弃 54.5 次回调（用户报的「web 上 FPS 到不了 120」）。修复后 120 Hz 面板实测 **120 fps / 0 丢弃 / 单帧 0.113 ms（帧预算 1.35%，GPU 光栅）**，demo 角落读数 `FPS:120`；同配置改 CPU 光栅（`putImageData`）为 6.66 ms/帧（**80% 预算**）——**GPU 光栅必要（已有的 WebGL2/Ganesh 即够），而 WebGPU 无收益且未编入**（wasm 版 Skia 为 `skia_use_webgpu=false`/`skia_enable_graphite=false`）。硬上限是**窗口所在显示器刷新率**（rAF 跟随面板；50 Hz 外接屏上任何后端都只能 50 fps）。帧率诊断：web 侧用编译期定义 `-D ASC_FRAME_STATS=1`（默认不编入产物），每秒把 `frames`/`loopcalls`/`skips`/`renderMs`/`rafPeriodMs`/`skip` 发到 `window.__ascFrameStats`。

- 浏览器目标（`--target wasm --package web`）的**服务端与同源策略**要求（阶段八十九·五十六）：① **`.wasm` 必须由服务端标为 `application/wasm`**。标成 `application/octet-stream`（部分简易静态服务器，以及 AgentPilot 内置预览面板）时 Chrome 会拒绝 `WebAssembly.instantiateStreaming`，控制台出现「流式编译失败 + 回退 ArrayBuffer」两行红色错误——这两行是**良性的**（emscripten 自动回退、页面照常运行，代价只是 wasm 被下载两遍），需要流式编译就得让服务端给对 MIME（本仓库验收服务器 `temp/netprobe2_server.py` 显式设了它）。② **跨源图片**（`Loader.load(http(s)://…)`）受同源策略约束：图片在浏览器里能*显示*但**读不到像素**，而 Skia 上屏正需要像素，故 CDN 必须回 `Access-Control-Allow-Origin`。实测 `meeting.talkmed.com/img/*.png` **没有**该头，故 `examples/url-test` 的两个 URL 在 web 上只能得到如实指名 CORS 的 `ioError`（native/`adl` 侧正常——curl 不受同源策略约束）。细节见 [`docs/zh-cn/html5-web.md`](docs/zh-cn/html5-web.md) §2/§3.4/§6.10。

### 在 AIR 之外（增强，非对齐）

上面「当前限制」都在**对齐 AIR** 这条线上（AIR 有、我们还没补齐，或口径不同）。另外还有一条**完全不同**的线：在
AIR **未定义 / 不支持 / 根本没有对应物**的地方，本项目可以借「直接生成可读 C + 链接成熟生态」的架构红利做**增强**
——AIR 的能力上限被 AVM2 运行时 + Flash 沙箱锁死，而我们的产物是一份可读 C 再交给 `clang -O2`：能链
Skia/libcurl/SQLite、能吃 LTO/PGO、能与宿主 C 互调、能编到 native/WASI/web 或跑无窗口的服务端出图。

典型例子是 **SVG**：`Loader.load("*.svg")` 在 `adl 51.4.1` 下实测就是 `Error #2124: Loaded file is an unknown type.`
（AIR 的 `Loader` 三处规范一致地只支持 SWF/JPG/PNG/GIF，SVG 从不在范围内），所以「支持 SVG」属**增强**而非补平差距——
native 侧 `libsvg.a`/`libsksg.a`/`libexpat.a` 已构建且已在链接表，只差把 `SkSVGDOM` 接进解码路径；web 侧 Skia 未编 expat，
需重编。

**原则**：① **保真是底线**——AIR 已定义语义逐字对齐（`adl` 实测为准），增强不得改写；② **增强是增益**——只在
AIR 之外做，且必须 **opt-in**、不膨胀默认产物、**绝不静默**、跨端差异显式列出。判据很硬：同一输入 `adl` 能跑对而
我们跑不出 ⇒ 那是**遗留缺陷**（见 `TODO.md` 的 `### 遗留待开发`）；`adl` 本来就报错或该 API 不存在 ⇒ 我们做出来
才是**增强**（见 `### 增强待做`）。**15 项可增强清单**（已完成 3 项：多格式图片解码 WebP/BMP/ICO 实测零代码可用、LTO/PGO 开关、**SVG 运行时解码 native 半**（opt-in 具名开关 `--features svg`，web 需重编 Skia）；余 Lottie、RAW、原生着色器、FFI、服务端出图…）
与五条判定标准见 [`docs/zh-cn/enhancements.md`](docs/zh-cn/enhancements.md)，原则亦见
[`docs/zh-cn/as3-semantics.md`](docs/zh-cn/as3-semantics.md) §4/§5。

每个示例编译后会在旁边留下同名 `.c` 文件，可直接阅读编译器生成的 C 代码。

## 测试

运行 `node test.ts`（或 `npm test`）会编译并运行 `examples/` 下全部示例，逐项报告 pass/fail，任一失败以非零码退出。
此外它还会跑一组**独立的构建层断言**（`[manifest] …`，不计入示例计数）：校验构建清单 `targets` 按目标分层的行为（一份清单跨 native/wasm 分叉、replace 语义、CLI 叠加优先级、路径解析与非法键报错）。
