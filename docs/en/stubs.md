# Empty substitutes (shell classes)

> Inventory taken in stage 293. It answers one question: **how many classes were
> registered with an API shape and no backend so that the `talkmedmeeting`
> application would compile, and what does each of them actually deliver today?**
>
> Everything here is checkable: the mechanism is `emitShellClasses()` in
> `src/emit.ts`, the registrations are `shell(...)` calls in `src/symbols.ts`, and
> the behaviour is measured on this machine's AOT build (probe `temp/clip/t4.as`).

---

## 1. What "empty substitute" means in the code

`shell(name, fqn, super, ctorParams, staticConsts, fields, methods, …)` marks a
class `shell: true`, and `emitShellClasses()` then emits:

| Emitted | Content |
|---|---|
| `// ---- shell class X (pkg.X): API shape only, no backend ----` | the marker line; grep it for the full list |
| `X_ctor` / `X_new` | a **real** constructor: fields are assigned from same-named parameters, `Array`/`Vector` fields default to an **empty** collection rather than `NULL`, and the super constructor is called with parameters matched by AIR's name |
| every method / getter / setter | an **empty body**: `as_shell_unsupported("pkg.X.member")`, then the type's zero value |

`as_shell_unsupported()` prints one line to stderr —
`[as3-aot] not implemented by this build: <member>` — **at most 5 lines for the
whole process**, the rest are silent. That is not a swallowed error: it says
plainly that this build does not implement the member, and returns a documented
zero value.

So three different kinds of "empty" must be told apart:

1. **Fields and constants are real** (event classes, option classes,
   `ClipboardFormats`): the object carries what the caller passed and reflection
   sees it; there is simply **no code path that produces** such an event.
2. **Methods are shells** — calling one does nothing, returns
   `null`/`0`/`false`/`undefined`, and reports once on stderr.
3. **Capability bits are `false`** — static `isSupported`-style properties are
   always `false`, so `if (X.isSupported) …` **really skips**. That is the same
   rule as `desktop.md` §2: reporting `true` and then doing nothing would be a
   silent degradation.

## 2. The list (20 classes)

"App references" = number of files in the `talkmedmeeting` sources
(`E:/Works/eDoctor/talkmed-meeting-windows/src`, 989 `.as` files) that mention the
class name (counted in stage 293).

### 2.1 Data carriers: fields and constants are real (11)

| Class | Package | App refs | Delivers | Does not deliver |
|---|---|---|---|---|
| `ClipboardFormats` | `flash.desktop` | 3 | the 7 format-name constants (`text`/`html`/`richText`/`url`/`bitmap`/`fileList`/`filePromiseList`) | nothing missing (a constants class, **not a gap**) |

| `NativeDragEvent` | `flash.events` | 1 | 8 constants (including the `NATIVE_DRAG_ENTER`/`NATIVE_DRAG_DROP` the app really listens for), 7 fields | no OS drag source, so the event never arrives |
| `NativeProcessExitEvent` | `flash.events` | 8 | `EXIT`, `exitCode` (**`number`**, measured `typeof`) | **a real event**: dispatched by `NativeProcess` when the child exits. The invented `process` field is gone (`mxmlc`/`describeType` never had it); see `native-process.md` §1 |
| `NativeWindowBoundsEvent` | `flash.events` | 4 | `MOVE`/`MOVING`/`RESIZE`/`RESIZING`, `beforeBounds`/`afterBounds` | **the window really dispatches these** (`NativeWindow` is real); the instance is built by the window layer with measured geometry |

> `NativeWindowBoundsEvent` / `NativeWindowDisplayStateEvent` are model classes the
> window backend really uses; they appear in the shell list only because their
> member set is generated by the shell path. Both are **usable**.

### 2.2 Real capability gaps (4)

> Before stage 391 this table also carried `NativeProcess` / `NativeProcessStartupInfo`:
> `start()` now really creates a child (`CreateProcessW` on Windows, `fork`+`execv` on POSIX),
> the three pipes are live, the `exit` event is dispatched at the frame boundary, and the
> `executable`/`workingDirectory` setters throw the measured `#3214`/`#3215`. See
> [`native-process.md`](../en/native-process.md) for the contract, event order and the three
> honestly reported divergences.
>
> Before stage 363 this table also carried `NetworkInfo` / `NetworkInterface`. They are
> gaps no longer: `findInterfaces()` now enumerates interfaces for real through
> `getifaddrs`, which turns `NetworkInterface` / `InterfaceAddress` into genuine data
> classes (their member sets were corrected against adl measurements too). Contract and
> acceptance: `flash-net.md` §6.10.

| Class | Package | App refs | What a call does today (measured) | A real implementation needs |
|---|---|---|---|---|
| `StageWebView` | `flash.media` | 3 | `isSupported=false`; instance can be built; `location`/`title`/`viewPort` all `null`; `loadURL()` reports | an embedded browser (WebView2 / WKWebView) |
| `NativeDragManager` | `flash.desktop` | 1 | `isSupported=false`, `dropAction=null` (reports); `doDrag`/`acceptDragDrop` do nothing | an OS drag source and a drop target |
| `Microphone` | `flash.media` | 4 | `isSupported=false`; `names` an empty array (reports); `getMicrophone()` returns `null` (reports) | audio capture |
| `LocalConnection` | `flash.net` | 4 | `isSupported=false`; `send`/`connect`/`close` do nothing | AIR has **no** such transport (it is a Flash Player feature) and libraries only use it as an "am I local?" probe, so the empty shell is the **correct** answer |

## 3. Member-level reports

These are not whole substituted classes but members a real implementation
deliberately does not do (`as_shell_unsupported`, complete as of stage 293):

| Member | Reason |
|---|---|
| `BitmapData.encode("jpeg"/"webp")` | the vendored Skia is built with JPEG/WebP encoding off |
| `Camera.getCamera` / `.name` / `.names` | no camera capture |
| `CubeTexture.uploadFromByteArray` | cube faces are not uploaded from a ByteArray |
| `Texture.uploadFromByteArray` (mip > 0 / non-8-bit format) | that path is not implemented |
| `DisplayObject.cacheAsBitmapMatrix` | the renderer caches at the object's own resolution |
| `DisplayObject.mask` | the renderer does not apply masks (`clipDepth` masking is a different, implemented path) |
| `Error.getStackTrace` | no AS3 frame model |
| `ExtensionContext.createExtensionContext` / `.call` | no native-extension host (the `--air-app` ANE path is separate) |
| `File.openWithDefaultApplication` | no ShellExecute / `NSWorkspace.open` (`browseFor*` themselves have a native backend, see [`desktop-file-interaction.md`](desktop-file-interaction.md)) |
| `FileReference.download` / `requestPermission` | no backend for download or the permission prompt (`upload` / `uploadUnencoded` got a real native-curl backend in stage 388, see [`flash-net.md`](flash-net.md) §6.11). They report themselves and return rather than pretending the user cancelled — with no dialog or transfer, `data`/`name` can never be filled |
| `File.icon` contents | no icon extraction (`NSWorkspace.iconForFile`). An empty `Icon` plus a loud report; `bitmapDatas` answers an empty array (reading it on AIR 51.4 itself throws `#1069`) |
| `File.getVolumeByDrive` / `getVolumeByPath` | no volume enumeration (`getmntinfo`/`statfs`). `StorageVolume` itself is real and measured; what is missing is who constructs it |
| `DockIcon.bitmaps` (painting) | that backend does not paint a Dock icon bitmap |
| `NativeApplication.systemIdleMode` | this build never inhibits the system idle timer |
| `Clipboard.setData(richText, non-ByteArray)` | `Clipboard.html`'s type table requires a `ByteArray`; storing anything else would make `getData` hand back a type the format does not promise |

## 5. How to re-check

```bash
# every shell registration
grep -n "shell('" src/symbols.ts

# the generated marker, one line per shell class
grep -n "shell class" <generated .c>

# what one class really answers on this machine (probe style: temp/clip/t4.as)
node src/index.ts <probe>.as -o out --run
```

The criterion: `adl` runs it correctly and we cannot ⇒ **remaining defect** (belongs
in `TODO.md` under "remaining work"); `adl` also errors, or the API does not exist in
AIR at all ⇒ **enhancement**. All four real gaps above are of the first kind, except
where the platform physically has no such feature (`LocalConnection` has no transport
in AIR either).
