# External fixtures

Some example directories named throughout `docs/` and `TODO.md` are **not in this
repository**. They are read-only third-party trees cloned beside the repo, used as
`adl` reference baselines ("what AIR actually renders") rather than as regression
input. This file says why they are out, how the suite treats them, and what is
needed to reproduce an acceptance run that cites them.

## Why they are not tracked

Two independent reasons, and both apply to most of them:

1. **They are third-party engines.** Their sources are somebody else's; a
   checkout should not silently vendor a full 3D engine, and their language
   surface is far outside the compiler's subset, so they cannot be regression
   input. Compiling one as a directory unit fails by design
   (`test/examples.ts` `SKIP_DIRS`).
2. **Their build outputs are host-specific.** Each carries a generated
   executable plus `.c`/`.data`/`.html`/`.js` bundles that a rebuild overwrites.
   Committing those means a platform-specific snapshot lands in the tree and
   every local build dirties `git status` — the same defect that
   `examples/*.build.json` (generated by `--air-app`) had.

## The fixtures

| Directory | What it is | Upstream | Tracked |
|---|---|---|---|
| `examples/away3d-core/` | the away3d-core-fp11 engine (479 `.as`, 2017-02-07 snapshot, Apache-2.0) — the `adl` reference for the Stage3D / native-shader work (enhancement E6) | `https://github.com/away3d/away3d-core-fp11` | no |
| `examples/Flappy-Starling/` | Josh Tynjala's Flappy-Starling game — the full Metal/Stage3D end-to-end acceptance app | *not recorded in-repo* | no |
| `examples/air-starling-demo/` | the Starling framework plus its demo scene — read-only reference for the Starling API surface | *not recorded in-repo* | no |
| `examples/url-test/` | local AIR probe app for the `flash.net` / URL-loading comparison | *local, not cloned* | no |

All four left the repository in 阶段一百九十八 (away3d-core and air-starling-demo
had been tracked despite `TODO.md` and this repository's ignore rules already
recording them as external). Working copies stay on disk for local acceptance
runs; `git status` no longer sees them.

The two unrecorded upstreams are a real gap: the in-repo record is an
attribution without a locator. Whoever knows the origin should fill it in — it is
the only thing standing between these baselines and being reproducible.

## How the suite treats a missing fixture

`test/examples.ts` lists them in `SKIP_DIRS`, and a directory unit that is absent
is simply never enumerated (`readdirSync` does not see it). Either way the
outcome is a **skip, not a failure** — the fixtures are extra evidence, never a
pass condition. This is why `node test.ts` runs green on a fresh clone with none
of them present.

Listing a gitignored directory in `SKIP_DIRS` is not optional bookkeeping, and
this file used to say so wrongly: `examples/url-test/` was gitignored but *not*
listed, so a local clone **was** compiled as a directory unit
(`example: url-test/ (dir unit)`) while a fresh clone never ran it — one
`node test.ts` tested different things on different machines. 阶段一百九十八
added the entry. A directory that is not in the repository must not silently be
a regression input.

## Reproducing an acceptance run

For `away3d-core`, the ADL baseline is captured with the AIR reference compiler:

```sh
git clone https://github.com/away3d/away3d-core-fp11 examples/away3d-core
cd examples/away3d-core
AIRSDK_HOME=/path/to/AIRSDK_51.4.1 /path/to/AIRSDK_51.4.1/bin/mxmlc \
  -source-path src -swf-version 32 -output build/Basic_SkyBox.swf Basic_SkyBox.as
```

and the same tree is measured against our AOT output with `as-aot --air-app
<MAIN_CLASS>-app.xml --main-class <MAIN_CLASS>`, which writes
`<MAIN_CLASS>.build.json` beside the descriptor (a generated file — see
`.gitignore`). The per-fixture harness script that automates both halves lives at
`examples/away3d-core/build-and-run.sh` and, per 阶段一百零七, is deliberately
not tracked; the commands above are the part that matters.

## Reading the docs

Citations such as `examples/away3d-core/Basic_SkyBox.as` and
`examples/air-starling-demo/src/scenes/MovieScene.as` in `docs/` and `TODO.md`
are **records of measurements that were taken**, not instructions to a fresh
checkout. They stay as written — rewriting a measurement to point at a tree that
was not the one measured would be worse than a dangling path.
