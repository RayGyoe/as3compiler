# oop — 多态虚方法派发 + 对象字段访问（面向对象核心基准）

## 说明
定义 `Figure` 基类与 `Circle`/`Square`/`Rect` 三个子类，各自 `override` 虚方法 `area()`；
把 192 个异构对象装入 `Array`，循环 2000 万次通过基类引用调用 `area()` 并累加校验和。
测量 **虚方法派发（vtable）+ 对象字段访问 + 装箱数组元素解引用** 这一面向对象核心路径。

## 规模与结果
- 规模：3 层类继承 × 3 种子类，192 个对象，2000 万次虚派发
- 校验结果（四路一致）：`result=913853951`

## 性能（纯计算时间，3 次取中位数，越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 48 | 1.00× |
| JavaScript (Node v24) | 60 | 1.25× |
| **as3compiler** (→ C → cc -O2) | 50 | 1.04× |
| 原生 AS3 (AIR/mxmlc) | 623 | 12.98× |

## 分析
- **as3compiler 与 C 几乎一致（1.04×）**：AS3 的类被翻译为 C 结构体 + vtable，
  虚方法调用编译成一次函数指针间接调用、字段访问编译成一次直接内存访问，经 `-O2` 后
  与手写 C 的函数指针派发等价——这是「只翻译、优化交给 C 编译器」路线在面向对象
  代码上的直接验证，也是本套件此前唯一未覆盖的类别（原 6 个基准均为过程式/纯计算）。
- **原生 AS3 12.98×**：AVM2 的虚方法派发需动态属性查找 + 方法解析，对象字段访问经
  属性槽位间接寻址，`Array` 元素还需装箱/拆箱，叠加成本远高于一次函数指针调用。
- **JS 1.25×**：V8 对单态调用点（monomorphic call site）已能内联，故接近 C。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 原生 AIR 的 `adl` 启动开销（约 2.6s）不计入。
- 累加采用 `if (sum >= 1e9) sum -= 1e9` 有界校验和，保证 2000 万次累加不溢出 32 位整型且四路结果精确一致。
