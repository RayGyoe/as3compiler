# cjkscan — 大 CJK 文本上的码元翻译（`indexOf` / `lastIndexOf` / `charCodeAt` / `substring`）

## 说明

`bigscan` 的**非 ASCII 孪生**。同一套操作、同样的码元规模，只换内容：

| | `bigscan`（阶段四百四十一） | `cjkscan`（本项） |
|---|---|---|
| 每行 | 43 个 ASCII 字符 + `"\n"` | 43 个汉字 + `"\n"` |
| 每行字节 | 44 | 130 |
| 4000 行 | 176000 码元 / 176000 字节 | **176000 码元 / 516000 字节** |
| 码元 ↔ 字节 | 完全重合 | 1 : 3（每个汉字 3 字节） |

两个基准的**码元数完全相同**，所以唯一的自变量是「翻译能不能塌成恒等」：`bigscan` 里能，
`cjkscan` 里不能——码元数必须真的数出来。

四个相位各盯一类调用，因为它们的最优形状不同：

| 相位 | 调用 | 形状 |
|---|---|---|
| A | `indexOf(needle, p+1)` 单调推进 100×40 | 游标能续走 |
| B | `lastIndexOf(needle, 120000-j)` 从大往小 100×40 | 反向定位 + 命中处翻译 |
| C | `charCodeAt((q*5003) % 170000)` 20000 次 | 升序跨步（21 次里 20 次游标能续走） |
| D | `substring(o, o+20).length`（`o=(r*7919) % 170000`）20000 次 | 两次定位 + 一次新串求长 + 分配，同样升序跨步 |

> **C/D 不是随机访问**：两者都是「升序跨步」，一圈 21 次访问里 20 次游标能接着走，只有回绕那
> 一次要从头数。这是**顺序切分**的形状（分词器、行表、解析器），也是真实热路径的形状；真正随机
> 访问的成本见 §3 末尾的补测，本夹具不覆盖它。

只收 BMP 字符（无星光面）：星光面的 2 码元语义由 `examples/string-utf16-index.as` 与
`examples/string-cjk-scan.as` 钉住，本项要量的是**翻译成本随串长增长**，掺进代理对只会让
「一个字符占几码元」的账变模糊。

## 规模与结果

四路校验和一致：`result=1037144959`。

## 分析

### 1. 缺陷：非 ASCII 的 `lastIndexOf` 每次调用都走整条串

修复前 `as_str_lastIndexOf_from` 有两条路：

- **ASCII**：`as_u16_prefix_ascii` 判定整串纯 ASCII ⇒ 反向字节扫，`s[i] == sub[0]` 命中才
  `strncmp`，**命中即返回** ⇒ O(候选数)。
- **非 ASCII**：从字节 0 **正向走完整串**（`while (*p != 0 && u <= from)`），沿途每个字符都
  做一次 `strncmp`，最后返回最后一个命中的码元索引 ⇒ **O(from)**，与命中在哪里无关。

在 4000 行中文上，`lastIndexOf("狐狸", 120000)` 只要 0.48 ms/次，4000 次就是 1.9 s。相位分解
（同一支程序，四段各自计时，三次运行）：

| 相位 | 修复前 | 修复后 |
|---|---:|---:|
| A `indexOf` 单调 | 0 | 0 |
| **B `lastIndexOf` 从大往小** | **1903–1924** | **11** |
| C 升序跨步 `charCodeAt` | 88–90 | 88–89 |
| D 升序跨步 `substring` + `.length` | 840–849 | 836–845 |

### 2. 修法：扫**候选**而不是扫**字符**

```c
int last = as_u16_byte_of(s, from);          // from 的字节偏移（游标可续）
for (int i = last; i >= 0; i--) {
    if (((unsigned char)s[i] & 0xC0) == 0x80) continue;   // 续字节永远不是字符起点
    if (s[i] == sub[0] && strncmp(s + i, sub, sublen) == 0)
        return as_u16_unit_of(s, i);                      // 只在命中的那一次翻译
}
return -1;
```

三件事各自都是必要的：

1. **反向扫 + 命中即返回。** 与 ASCII 分支同一形状，于是「最后一个匹配」不需要知道前面的内容。
2. **跳过续字节。** 只有这样才能保证候选落在字符起点上，`strncmp` 就不会匹配到某个字符的
   内部。**这一步是安全的，不是启发式**：UTF-8 的引导字节是 `00–7F` / `C2–DF` / `E0–EF` /
   `F0–F4`，续字节是 `80–BF`，两者**不相交**——一个合法的 UTF-8 针（首字节是引导字节）不可能
   出现在续字节位置。
3. **上界是 `from` 的*字节*偏移。** 码元索引对字节偏移单调，所以「起点码元 ≤ from」与「起点
   字节 ≤ byte_of(from)」等价；星光面的低半码元也落在同一个字符上，不会漏。

配套的第二笔：`as_u16_unit_of` 原来只支持**正向**续走（游标在目标之前才能省），而 B 相位是从大
往小走——于是每次都要从字节 0 重数一遍，等于把刚省下的那趟又付了回去。补上镜像的反向续走
（退一格、跨过续字节、4 字节字符扣 2 个码元）之后，B 相位从 1903 ms 落到 11 ms。

### 3. 剩下的 D 相位：表示成本，不是缺陷

`substring` 的每一次调用都要把码元索引换成字节偏移，而这一步没有索引可用——游标只能覆盖
「不比上次更小」的访问，回绕那一次仍要重数。这一项两边同形
——C 列也走同样的路（两次 `byte_of_unit` + 拷进 256 字节栈缓冲 + 数码元），它的 D 相位
430–463 ms，我们 836–845 ms；差额是「我们还要分配一个 GC 字符串」：C 的切片落在栈上，我们
要从 GC 堆里取块、还要维护 `as_str_len` 的长度 memo。所以：

- **双向定位（本轮试过，否）**：目标在后半段时从串尾倒着走。在这个夹具上 **0%**——D 是升序
  跨步，游标本来就罩得住。真随机访问另做了 C 原型补测（`temp/cjkscan/cphases_rnd{,_bi}.c`，
  同一份代码只把索引换成 LCG）：D 相位 **3121 → 2649 ms（−15%）**，**不是**原先估的 2×
  ——走路（walk）不是这块的唯一成本，所以 `min(u, L-u)` 省下的那半并没有按比例兑现。运行时里
  它还要额外知道**字节长度**（`as_str_len` 的 2 槽 memo 只存码元数），要么每串多一次 `strlen`、
  要么扩 memo ⇒ 更不容易成立，故**否**。
- **能根治但要新结构**：per-string 的**采样检查点**（每 1024 码元存一个字节偏移），随机访问从
  `O(L)` 变 `O(1024)`；代价是每个被缓存的串带一张小表 + 失效策略（串是 GC 对象，指针会复用，
  现有 `as_str_len` / `as_u16_cursor` 的「同指针即同内容」前提要跟着扩）。
- **真正根治**：把字符串改成 UTF-16 存储（表示变更，用户裁决项，不在本阶段）。

后两项未做，登记在 `TODO.md` 遗留表（本阶段只把「可证明是浪费」的那部分拿掉）。

### 4. 被否：给新串 stamp 长度 memo

`as_u16_take` 天然知道切片是 `b - a` 个码元，顺手写进 `as_str_len` 的 2 槽 memo，理论上让
`.length` 免掉一次 60 字节的扫描。实测 **948 → 937 ms（−1%）**，在噪声内 ⇒ **否**（测量上的平手
就是拒绝）。D 相位的 845 ms 里，`as_str_len_wide` 对 60 字节的切片本来就只值几纳秒。

### 5. 语义不变的三重证据

修复只动实现，不动语义，这一点必须**证明**而不是声称：

1. **差分模糊**：400 组随机串/针/`from`（字母表含 ASCII、中文、重音字母、`\n`），
   800 个断言（`indexOf` + `lastIndexOf` 各 400）对 **V8 的 UTF-16 原生语义**逐一比对：
   **800/800 通过**；同一份 `fuzz.as` 用修复前的源码编译也**800/800** ⇒ 差异只是性能。
   生成器与程序在 `temp/cjk/genfuzz.js` / `temp/cjk/fuzz.as`。
2. **`examples/string-cjk-scan.as`（31 条断言）** 的期望值全部与 `adl 51.4.1` 逐条核对
   （`temp/cjk/air/`，`ok=31` 无 FAIL）：覆盖 176000 码元串上的 `lastIndexOf` 逐值扫描、
   空针、负 `from`、`from` 超长、跨字符的针、CJK 前面拼 ASCII 之后整串不再是纯 ASCII 的形态、
   以及 `substring` / `charAt` / `charCodeAt` 的码元索引。
3. **四路校验和**：`run.py` 打 `OK`（`result=1037144959`）。

### 6. 与 `bigscan` 合起来看

| 基准 | 缺陷 | 修复 | 读数 |
|---|---|---|---:|
| `bigscan`（176 KB ASCII） | 翻译层每字符walk | ASCII 探测 + 游标续走 + 反向扫（阶段四百四十一） | 38 → 10 ms（−73.7%） |
| `cjkscan`（176000 码元 CJK） | 非 ASCII `lastIndexOf` 整串走 | 反向候选扫 + 双向游标（本阶段） | 2872 → 953 ms（−66.8%） |

两者合起来覆盖了翻译层仅有的两种形态：**能塌成恒等**与**不能塌**。
