# fib — 递归 Fibonacci（整数基准）

## 说明
递归计算 `fib(40)`，测量函数调用与 32 位整数运算性能。四路采用相同的朴素递归算法。

## 规模与结果
- 输入：`n = 40`
- 校验结果（四路一致）：`result=102334155`

## 性能（纯计算时间，3 批 × 各 3 次，取中位数；越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 290 | 1.00× |
| JavaScript (Node v24) | 797 | 2.75× |
| **as3compiler** (→ C → cc -O2) | 291 | 1.00× |
| 原生 AS3 (AIR/mxmlc) | 3615 | 12.47× |

## 分析
- **as3compiler 与 C 持平（1.01×，即差异在噪声内）**：生成的 C 递归经 `-O2` 后与手写 C
  等价，验证了「只翻译、优化交给 C 编译器」的路线在调用密集型整数代码上不损失性能。
  三批读数 288 / 286 / 289 ms，跨批次稳定；与上一轮（291 ms）偏差 −1%。
- **JS 2.79×**：V8 对未优化的朴素递归（无尾调用、每层两分支）仍有逐调用开销。
- **原生 AS3 12.64×**：AVM2 的函数调用与 `int` 装箱/拆箱是主要开销；这也说明
  「消除调用开销」是 AOT 相对 AVM2 的最大收益来源之一。
- 本基准**零堆分配**，因此不受 GC 策略影响（见 `README.md` 的 GC 专项一节）。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 原生 AIR 的 `adl` 启动开销（约 2.6s）不计入。
