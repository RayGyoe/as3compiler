# binarytrees — 递归二叉树分配/遍历（对象分配基准）

## 说明
按深度递归构造完全二叉树并遍历计数，测量对象分配与递归遍历性能。
`maxDepth = 14`（约 320 万节点），规模为原生 AS3 与无 GC 的 as3compiler 折中。

## 规模与结果
- `maxDepth = 14`；输出三部分：`stretch` 计数、循环 `sum`、`longLived` 计数
- 校验结果（四路一致）：`result=65535,3123888,32767`

## 性能（纯计算时间，3 次取中位数，越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 73 | 1.00× |
| JavaScript (Node v24) | 32 | 0.44× |
| **as3compiler** (→ C → cc -O2) | 81 | 1.11× |
| 原生 AS3 (AIR/mxmlc) | 353 | 4.84× |

## 分析
- **as3compiler 1.11× C（已纳入真实 GC 开销）**：本基准现已周期性调用 `System.gc()`
  （每 2048 次构造 + 每深度收尾各一次），在 320 万 `Node` 的持续分配压力下真正执行
  mark/sweep。此前版本**从不触发 GC**（`gc_step` 只在帧边界安全点调用，控制台 `main()`
  到不了），是靠分配块小、内存够大才「碰巧」跑完，数值上看似 0.66× 快于 C，本质是
  **静默泄漏**。纳入真实 GC 后回落到 1.11×，这 0.11 的代价就是精确 GC 的停顿。
- **JS（0.44×）仍快于 C**：V8 的分代 GC + JIT 在分配密集型负载上优于手动 `malloc/free`；
  C 版含显式 `freeTree` 递归释放，属算法完整性的固定开销。
- **原生 AS3 4.84×**：AVM2 的对象分配 + 标记清除 GC 开销显著。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 原生 AIR 的 `adl` 启动开销（约 2.6s）不计入。
