# mandelbrot — Mandelbrot 集合计数（浮点内层循环基准）

## 说明
对 `size=1500` 的像素网格做 Mandelbrot 逃逸判定（每像素最多 50 次迭代），
统计收敛点的数量。测量纯 `double` 算术与紧内层循环性能，无任何对象分配。

## 规模与结果
- `size = 1500`（1500×1500 像素，每像素 ≤50 次迭代）
- 校验结果（四路一致）：`result=894105`

## 性能（纯计算时间，3 批 × 各 3 次，取中位数；越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 95 | 1.00× |
| JavaScript (Node v24) | 123 | 1.29× |
| **as3compiler** (→ C → cc -O2) | 95 | 1.00× |
| 原生 AS3 (AIR/mxmlc) | 358 | 3.77× |

## 分析
- **as3compiler 1.00×（与 C 持平）**：分配自由的纯浮点循环，生成的 C 与手写 C 无差别 —— 浮点部分
  完全交给 `-O2`（含向量化/指令选择），前端不做任何数学改写。三批读数 94 / 95 / 94 ms。
- **JS 1.28×**：V8 已能较好优化数值循环，但仍略慢于 AOT 的机器码。
- **原生 AS3 3.74×**：AS3 的 `Number`（double）运算本身不算慢，差距来自循环控制与
  局部变量存取的运行时开销。
- 本基准**零堆分配**，不受 GC 策略影响。
- 整数 `%` 的零除数守卫（`as_int_rem`/`as_uint_rem`，v0.3.127）与本项无关：源码不含取模运算。
- 与上一轮（96 ms）偏差 −2%，属噪声。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 原生 AIR 的 `adl` 启动开销（约 2.6s）不计入。
