# mandelbrot — Mandelbrot 集合计数（浮点内层循环基准）

## 说明
对 `size=1500` 的像素网格做 Mandelbrot 逃逸判定（每像素最多 50 次迭代），
统计收敛点的数量。测量纯 `double` 算术与紧内层循环性能，无任何对象分配。

## 规模与结果
- `size = 1500`（1500×1500 像素，每像素 ≤50 次迭代）
- 校验结果（四路一致）：`result=894105`

## 性能（纯计算时间，3 批 × 各 3 次，取中位数；越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 95 | 1.00× |
| JavaScript (Node v24) | 122 | 1.28× |
| **as3compiler** (→ C → cc -O2) | 122 | 1.28× |
| 原生 AS3 (AIR/mxmlc) | 355 | 3.74× |

## 分析

### 1. 1.28× 的根因：`-ffp-contract=off`（阶段九十六，AS3 语义要求）
本项是**纯 `double` 内层循环**（`zr*zr - zi*zi + cr`、`2.0*zr*zi + ci`），而 clang 默认
（`-ffp-contract=on`）会把它收缩成单条 **FMA**（一次舍入）。但 AS3 的 `Number` 算术要求
**每步一次舍入**（`AGENTS.md` §2.4），因此在 `src/build.ts` 的 `fpFlags()` 中全后端固定
`-ffp-contract=off`。代价在本项上很明显：

| 同一份生成 C（`benchmarks/mandelbrot/mandelbrot.as` 编译产物） | 耗时 |
|---|---:|
| `cc -O2`（clang 默认，contract **on**，等同 C 基线的编译方式） | **93 ms** |
| `cc -O2 -ffp-contract=off`（**本项目实际口径**） | **119 ms** |

即：**这 +28% 就是「不做 FMA 融合」的代价，不是 codegen 退化**。而 C 基线（95 ms）由
`run.py` 用裸 `cc -O2` 编译，**它的算术与我方不等价**（它只舍入一次）—— 所以在含浮点乘加的
基准上，`AOT vs C` 不再是「同一算术的两种实现」的比较。若给 C 侧也加 `-ffp-contract=off`，
两者回到同一口径。

> 历史：v0.4.3 报告的本项为 95 ms（1.00× C）——那是阶段九十六**之前**的读数。
> 本项从那时起的 95 → 122 ms 一直是「无归因的回退」，本轮定位到这一个标志，并做了 A/B 实证。

### 2. 其余数字
- **三批读数 134 / 120 / 122 ms**（第一批偏高属冷启动/调度噪声，后两批稳定）。
- **JS 1.28×**：V8 已能较好优化数值循环，与本项 AOT 同速。
- **原生 AS3 3.74×**：AS3 的 `Number`（double）运算本身不算慢，差距来自循环控制与
  局部变量存取的运行时开销。
- 本基准**零堆分配**，不受 GC 策略影响。
- 整数 `%` 的零除数守卫（`as_int_rem`/`as_uint_rem`，v0.3.127）与本项无关：源码不含取模运算。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 原生 AIR 的 `adl` 启动开销（约 2.6s）不计入。
