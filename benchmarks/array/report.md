# array — 装箱数值 Array 迭代与累加（as_value 装箱路径基准）

## 说明
填充 2000 万个整数的普通 `Array`（非 `Vector.<T>`，元素经 `as_value` 动态装箱），
循环读下标累加有界校验和。测量 **`Array` 索引访问 + `as_value` 装箱/拆箱 + 整型累加** 这一
AS3 最常见的数据结构路径，与 `spectralnorm`（`Vector.<Number>` 无装箱）互为对照。

## 规模与结果
- 规模：2000 万元素（`(i * 31) % 997`），一次全量遍历累加
- 校验结果（四路一致）：`result=959996015`

## 性能（纯计算时间，3 批 × 各 3 次，取中位数；越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 21 | 1.00× |
| JavaScript (Node v24) | 23 | 1.10× |
| **as3compiler** (→ C → cc -O2) | 119 | 5.67× |
| 原生 AS3 (AIR/mxmlc) | 131 | 6.24× |

## 分析

### 1. 5.67× 的根因是「每元素体积」，不是「访存指令数」
`as_value` 是 24 B 的 tagged union（`int tag` + 填充 + `double num` + `void* ptr`），而
C 参考版是 4 B 原生 `int`。20 M 元素的遍历分别搬运：

| 实现 | 每元素 | 总搬运量 | 耗时 | 有效带宽 |
|------|-------:|---------:|-----:|---------:|
| C | 4 B | ≈ 80 MB | 21 ms | ≈ 3.8 GB/s |
| as3compiler | 24 B | ≈ 480 MB | 119 ms | ≈ 4.0 GB/s |

**两者都跑在内存带宽上、且带宽几乎相同**（≈4 GB/s），因此耗时比（5.67×）≈ 体积比（6×）。
这说明：AOT 的装箱代码本身并不低效（没有额外的分派/边界检查开销），差距纯粹来自
AS3 语义要求每个元素携带 tag，无法像 `Vector.<T>` 那样压成 4 B。

> 反面参照 `oop`：同样走 `Array` 装箱（192 元素），因工作集 ≈4.6 KB 常驻 L1，
> 装箱开销被完全吸收，结果为 1.12× C。**装箱税的可见程度取决于工作集是否超出缓存。**

### 2. 绝对耗时仍反超 AVM2（119 ms vs 131 ms）
即便同为装箱路径，AOT 的装箱/拆箱是**确定性 tagged-union 读写**，而 AVM2 还要叠加
动态属性槽位与分派，故 AOT 快约 1.10×。这是本套件中 AOT 相对原生优势最小的一项 ——
也是唯一一项「原生解法与 AOT 解法在语义上等价、无机器可消」的负载。

本轮数字与上一轮完全一致（119 ms），**未受 v0.3.137 自动回收影响**：填充阶段不计入计时，
且遍历阶段零分配，故不会触发 `gc_alloc` 的分配阈值。

### 3. 使用建议
对照 `spectralnorm`：同为数值容器，`Vector.<Number>`（无装箱）在 AOT 下可达 1.00× C，
一旦改用普通 `Array` 就是 5.67× C。**数值密集代码用 `Vector.<T>`，动态异构集合才用 `Array`。**

## 历史修正
- 旧报告记录的 **C 基线 43 ms 不正确**：那次测量与 `array_asc` 因 `gc_alloc` 超大分配
  死循环、占用约 415 GB 虚拟地址空间发生在同一时段，整机内存压力污染了读数，使相对倍数
  失真为 2.86×。卡死修复后 C 基线稳定在 21–22 ms（本轮三批 22 / 21 / 22），AOT 侧
  119 ms（三批 119 / 119 / 119）。
- **`gc_alloc` 超大分配死循环**（本基准曾触发：`Array` 值缓冲 2 倍扩容到 65536 时
  = 65536 × 24 B = 1.5 MiB > 1 MiB 固定段，导致无限递归 `malloc`）已修复，现在为
  超大请求分配专用段。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 填充阶段（`push` 2000 万次）不计入计时，仅累加遍历计入。
- 累加采用 `if (sum >= 1e9) sum -= 1e9` 有界校验和，保证不溢出 32 位整型且四路结果精确一致。
