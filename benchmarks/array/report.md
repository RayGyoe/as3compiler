# array — 装箱数值 Array 迭代与累加（as_value 装箱路径基准）

## 说明
填充 2000 万个整数的普通 `Array`（非 `Vector.<T>`，元素经 `as_value` 动态装箱），
循环读下标累加有界校验和。测量 **`Array` 索引访问 + `as_value` 装箱/拆箱 + 整型累加** 这一
AS3 最常见的数据结构路径，与 `spectralnorm`（`Vector.<Number>` 无装箱）互为对照。

## 规模与结果
- 规模：2000 万元素（`(i * 31) % 997`），一次全量遍历累加
- 校验结果（四路一致）：`result=959996015`

## 性能（纯计算时间，v0.4.93 轮单批 × 内部 3 次取中位数；越低越好）

| 实现 | 耗时 (ms) | 相对 C |
|------|----------:|-------:|
| C (cc -O2) | 20 | 1.00× |
| JavaScript (Node v24) | 23 | 1.15× |
| **as3compiler** (→ C → cc -O2) | **118** | **5.90×** |
| 原生 AS3 (AIR/mxmlc) | 131 | 6.55× |

> v0.4.93 轮次（单批 × 内部 3 次中位数）；C/JS/AIR 三列与上一轮漂移 −0…−9%。
> **本项与 v0.4.92 持平（119 → 118 ms）**，但那个「持平」是**护栏换来的**：
> 本轮把热路径的 int 强转从原始解箱换成 AS3 强转（`unboxAny` 家族收口），
> 直接调用通用强转助手会让 clang 拒绝内联（`inline cost 595 > 325`，116 → 169 ms），
> 故新增可内联小包装 `as_v_int_cast`（tag 1/2 直取、其余转交）——见 §1 的生成 C 与 §5。

## 分析

### 1. 根因是 **`int` 累加器被迫走 `double` 域**，不是内存带宽

计时区只有一句：

```as3
sum += a[j];          // sum:int, a[j]:*（动态）
```

生成 C 把它翻译成语义完整的**动态加法**：

```c
g_sum = as_v_int_cast(as_add_v(as_v_num((double)(g_sum)),
                               as_array_get(as_req_obj((void*)g_a), g_j)));
```

（v0.4.92 起是 `as_v_int_cast`，在此之前是只读数字槽的 `as_v_int_val` —— 后者对动态值
不看 tag，字符串元素会静默给 0；改成强转后需要内联护栏，见文件名下的表格说明与 §5。）

即每轮：`int → double`（`scvtf`）→ 动态加法 → `double → int`（`fcvtzs`）。
这条 **`int→double→int` 往返构成循环携带依赖链**（约 12 周期），是全部差距所在。

**变体归因**（同一份生成 C，逐层替换，各 3 次取中位；`temp/bench/invest/attr.py`）：

| 变体 | 耗时 | Δ | 结论 |
|---|---:|---:|---|
| v0 原样 | 118 ms | — | 基线 |
| v1 去动态加法（保留取值 + 守卫 + 24 B 装箱读） | **21 ms** | −97 | **整个差距就在这里** |
| v2 v1 + 去 `as_req_obj` 守卫 | 21 ms | −0 | 守卫 **0 ms** |
| v3 v2 + 去 `as_array_get` 边界检查 | 18 ms | −3 | 边界检查 3 ms |
| v9 保留 double 往返、去 `as_to_int32`/结构解箱 | 119 ms | +1 | 不是 `as_to_int32`，也不是装箱结构 |
| v13 特化 `int + *`，热路径用**整数加法** | **21 ms** | −97 | 去掉往返即可全恢复（结果一致） |

**决定性对照 —— 纯 C 里同样的两种写法**（`temp/bench/invest/arrayattr/micro.c`，20 M 次）：

```
int_add              time=30     s = s + a[j];
int_double_roundtrip time=116    d = (double)((int)d + a[j]);
```

同一条访存、同一个数组、**只差 int↔double 往返**：**30 → 116 ms（3.9×）**。
所以这是**纯 C 也一样**的代价，与我们编译器的代码生成无关。

### 2. 修正旧结论：**不是带宽瓶颈，内存带宽有大量余量**

旧版本报告把 5.27× 归因为「每元素体积」（`as_value` 24 B vs `int` 4 B，480 MB vs 80 MB），
并用「480 MB ÷ 116 ms ≈ 4.1 GB/s，与 C 的 ≈3.6 GB/s 同量级」佐证「带宽受限」。

**该推理已被 v1 证伪**：v1 **保留全部 24 B 装箱读与 480 MB 搬运**，仅去掉依赖链，即降到 21 ms
—— 等效带宽 **≈ 22.8 GB/s**（≈ 旧口径的 5.5 倍）。可见旧口径的「≈4 GB/s」不是机器的带宽上限，
而是**依赖链把吞吐压到了延迟极限**；两组数字恰好都约等于 4 GB/s 纯属巧合。
结论方向（装箱代码本身不低效）不变，但机理是**延迟受限**，不是**带宽受限**。

其余未走动态加法的成分也都可忽略：`as_add_v` / `as_array_get` / `as_req_obj` / `as_v_to_number`
经 `-O2` **全部内联**（`clang -S` 后的汇编里没有对它们的 `bl`），tag 检查已优化成位掩码 + 单条
`umaddl` 步长寻址。

### 3. 该代价是 AS3 语义必需，AIR 也付（且付得更多）

`sum:int` 与动态操作数相加时，AS3 规定算术在 **Number（double）域**进行，再把结果 ToInt32 回
`int`——所以往返无法省略。**AIR 自己就是 131 ms（6.55× C）**，比我们更慢，佐证这是语义代价。

> `v13` 的 21 ms 是**改了算术域**（`a + (int)b.num`）换来的，对**小数元素**会给出不同结果
> （`sum=0; a[0]=1.5` ⇒ AS3 得 1，整数域写法得 0），因此**不是**可采纳的修法，只用于归因。

### 4. 使用建议
对照 `spectralnorm`：同为数值容器，`Vector.<Number>`（无装箱）在 AOT 下可达 0.81× C，
一旦改用普通 `Array` 就是 5.90× C；若累加器又恰好是 `int` 而与动态元素相加，还会再叠加
本节的往返代价。**数值密集代码用 `Vector.<T>` + `Number` 累加器，动态异构集合才用 `Array`。**

### 5. 强转家族收口后的内联护栏（v0.4.93）

本项热循环里那次「动态元素 → `int`」在语义上**必须走 AS3 强转**（`as_v_to_int`），
但通用强转助手要调 `as_str_to_number`（ES3 ToNumber，含 hex/空白/`Infinity` 解析）⇒
`clang -Rpass-missed=inline` 实测 **`inline cost: 595` > 阈值 325**，热循环代价 **116 → 169 ms（+45%）**。
拆成「通用助手 + 单调用者小包装」也无效（clang 对单调用者会折回合并）。
**可用形态**：让通用助手保持多调用者、另加两个极小包装 `as_v_int_cast`/`as_v_uint_cast`
（tag 1/2 直取 `v.num`，其余 tag 转交通用助手——语义与通用助手**逐 tag 相同**），
实测 **117–118 ms** ⇒ 本项与 v0.4.92 持平。

（历史 A/B：`as_v_int_val` 116 ms / 调用通用助手 169 ms / `as_v_int_cast` 117–118 ms。）

## 历史修正
- 旧报告记录的 **C 基线 43 ms 不正确**：那次测量与 `array_asc` 因 `gc_alloc` 超大分配
  死循环、占用约 415 GB 虚拟地址空间发生在同一时段，整机内存压力污染了读数，使相对倍数
  失真为 2.86×。卡死修复后 C 基线稳定在 21–22 ms（v0.4.3 轮次三批 22 / 21 / 22，
  v0.4.92 轮次三批 22 / 22 / 22），AOT 侧 v0.4.3 为 119 ms（三批 119 / 119 / 119）、
  v0.4.92 与 v0.4.93 均为 118–119 ms。
- **旧「带宽受限」机理已由本报告 §2 证伪**（保留等量访存、去依赖链即 5.5× 提速）。
- **`gc_alloc` 超大分配死循环**（本基准曾触发：`Array` 值缓冲 2 倍扩容到 65536 时
  = 65536 × 24 B = 1.5 MiB > 1 MiB 固定段，导致无限递归 `malloc`）已修复，现在为
  超大请求分配专用段。

## 计时口径
- 四路均内部计时纯计算（C: `clock_gettime` / JS: `hrtime` / as3compiler: `Date.getTime` / 原生 AS3: `getTimer`）。
- 填充阶段（`push` 2000 万次）不计入计时，仅累加遍历计入。
- 累加采用 `if (sum >= 1e9) sum -= 1e9` 有界校验和，保证不溢出 32 位整型且四路结果精确一致。
- 变体归因脚本与产物留 `temp/bench/invest/`（`attr.py` / `array_opt.py` / `array_chain.py`），
  测量后不随基准提交。
